# L04 · 诊断世界模型：从组件到部署

评估应从组件在智能体闭环中的作用开始，而不是从架构名称开始。低重建损失不能证明动作正确改变了预测未来，高 episode return 不能揭示成功是否依赖可利用的模型漏洞，视觉逼真的 rollout 也不能证明规划器会选择安全动作。

**核心原则**：*先定位失效的接口，再选择能够暴露该故障的指标。*

本讲分为四层：

- **诊断框架**：表示、单步动力学、长时程 rollout、任务信号、规划与部署
- **模型实例**：用 Dreamer、TD-MPC、MuZero、STORM 与 Diamond 展示框架如何随模型接口变化
- **跨模型故障**：时程漂移、物理不一致、动作条件失效与模型漏洞利用
- **部署评测**：校准、延迟、迁移、安全与系统级可靠性

建议完成 P03 与 P04 后阅读本讲，并在完成 P05 时使用这套框架，而不是把 P05 当作前置要求。手中已有两个训练系统后，诊断规则会变得具体。
